## 하위 증상 분류
- **SQL 데이터 미수집**: JSPD 위빙 차단으로 SQL 수집이 안 되는 현상 (IMX-9452)
- **SQL 수집 설정 미동작**: 설정 파일 참조 경로 차이로 수집 필터가 동작하지 않는 현상 (IMX-9356)
- **SQL 정렬 실패**: SQL 포맷터 벤더 하드코딩/라이브러리 초기화 실패로 정렬 불가 (IMX-9235)
- **E2E 데이터 유실**: TCP 스트림 바이트 정렬 불일치로 E2E 데이터 유실 (IMX-9483)
- **패킷 미전송**: 전송 메소드 분기 누락으로 패킷이 전송되지 않는 현상 (IMX-9604)
- **데이터 중복 삽입**: 패치 부작용으로 중복 방지 로직 무효화, 테이블 비대화 (IMX-8964)

## 공통 패턴

- **패치/업그레이드 부작용**: 특정 이슈 수정 과정에서 다른 기능의 분기/필터 로직이 의도치 않게 변경되어 수집 차단이나 중복 삽입이 발생하는 패턴.
- **버전별 설정 파일 차이**: JSPD 설정(imx.prop vs jspd.prop.ini)의 참조 파일이 버전에 따라 다르고, 이를 혼동하면 설정이 적용되지 않음.

## 조사 시 체크포인트
1. `jspd.local.advice` 파일에 `-oracle/*`, `-com/*` 등 와일드카드 제외 패턴이 있는지 확인
2. JSPD 버전 업그레이드 이력 확인 — 이전 버전에서 정상이었는지
3. JSPD 버전에 따라 SQL_DETAIL_ELAPSE_LIMIT 설정 파일이 다름: base/hotfix는 imx.prop, 2509.04 이후는 jspd.prop.ini
4. 2계층 필터 구조 확인: JSPD(Java) 필터 + imxtxn(Native) 필터가 독립적으로 동작
5. PJS 로그에 `NoClassDefFoundError: Could not initialize class gudusoft.gsqlparser.c` 에러 확인
6. 고객사 DB 타입 확인 — Oracle/DB2 외 타입(SQLSERVER, PostgreSQL, MariaDB)에서 SQL 정렬 실패 가능
7. pootprinter 로그에서 `StreamInput boolean parsing error` 또는 `unexpected byte [0x..]` 에러 확인
8. 에러 발생 시점 전후 거래량 급증 여부 확인
9. DGM/PJS/DB 재기동이 아닌 **pootprinter 재기동**으로 해결되는지 확인
10. `SEND_TXN_DATA_DIRECTLY` 설정값 확인 (true=txn spec out 모드)
11. 전송 메소드별 분기 처리 일관성 확인 (일반 메소드에는 있고 변형 메소드에는 누락되는 패턴)
12. 패치 적용 후 의도하지 않은 테이블의 insert 주기가 변경되었는지 DB에서 time 컬럼 기준으로 확인
13. insert SQL에 NOT EXISTS 등 중복 방지 조건이 유지되고 있는지 확인
