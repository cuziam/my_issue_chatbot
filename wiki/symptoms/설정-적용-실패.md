## 하위 증상 분류
- **설정 CRUD 오동작**: 설정 테이블 유니크 키 변경 후 DTO/WHERE절 미반영으로 CRUD 실패 (IMX-9416, IMX-9608)
- **설정 미적용**: 설정값의 매칭 규칙(startsWith/endsWith) 오해로 필터가 적용되지 않는 현상 (IMX-9675)
- **신규 타입 미반영**: 새 에이전트 타입 추가 시 기존 UI 분기에서 해당 타입 미처리로 탭/버튼 미동작 (IMX-9536)
- **연계 타입 불일치**: 연계 제품 간 에이전트 타입명 불일치로 연계 기능 동작 실패 (IMX-9371)

## 공통 패턴

- **부모-자식 관계 연쇄 처리 부재**: 설정 화면에서 부모-자식 관계 데이터를 수정할 때, 자식 엔티티에 대한 연쇄 처리 로직이 불완전한 패턴. 프론트엔드에서 변경 대상과 제외 대상을 혼동하거나, 백엔드에서 관련 필드를 함께 초기화하지 않아 데이터 불일치 발생.
- **분기 추가 누락**: 새 타입/기능 추가 시 기존 if-else/switch 분기에 해당 타입을 추가하지 않아 미동작.

## 조사 시 체크포인트
1. DB 테이블에 새 컬럼이 추가되었는데 백엔드 DTO/Entity에 해당 필드가 반영되었는가?
2. 프론트엔드 save()/delete() 요청에서 새 필드를 API로 전송하고 있는가?
3. Repository의 WHERE절이 유니크 키를 완전히 포함하는가? (DELETE, UPDATE 모두 확인)
4. 설정값의 매칭 방식 확인 (startsWith/endsWith/contains/정규식 등)
5. 설정값이 대소문자 구분하는지 확인
6. 설정 반영 시점 확인 (즉시 적용 vs 재기동 필요)
7. 새 에이전트 타입이 추가되었을 때, monitorType별 분기 코드에 해당 타입이 포함되어 있는지 확인
8. `collectAgentListByMonitorType` 등 에이전트 분류 함수에서 새 타입이 별도로 분류되는지 확인
9. InterMax 내부 타입명(CDM, LOG 등)과 외부 연계 제품이 사용하는 타입명(CD 등)이 일치하는지 확인
10. DataModule.js의 타입 정규화 로직이 연계 API 응답에도 적용되는지 확인
