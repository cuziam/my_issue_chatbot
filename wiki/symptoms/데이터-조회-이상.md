## 하위 증상 분류
- **데이터 미조회**: DB에 데이터 존재하나 JOIN 조건/필터 불일치로 UI에 미표시 (IMX-9302, IMX-9605)
- **조회 데이터 중복**: 비동기 API 로딩 플래그 관리 오류로 조회 버튼 연속 클릭 시 데이터 N배 표시 (IMX-9632)
- **조회 조건 불일치**: 선택 조건과 실제 조회 결과가 다른 현상, 특수문자 에이전트명 매칭 실패 (IMX-9668)
- **첫 조회 실패**: 비동기 초기화 미완료로 첫 조회 시 에러, 재조회 시 정상 (IMX-9668)

## 공통 패턴

- **JOIN/필터 조건 불일치**: DB에 데이터가 존재하지만 UI에서 표시되지 않는 경우, 조회 SQL/API의 필터 조건이 데이터와 불일치하는 것이 근본 원인. (1) INNER JOIN 참조 테이블에서 레코드 삭제 시 조회 누락 (2) 스키마 변경으로 신규 필터 조건이 추가되었으나 기존/이관 데이터에 해당 값이 없어 필터에서 제외.
- **비동기 로딩 타이밍**: 프론트엔드에서 비동기 초기화가 완료되기 전에 조회를 시도하면 에러 발생. 복수 비동기 API의 완료 시점 관리가 부정확하면 중복/누락 발생.

## 조사 시 체크포인트
1. 조회 SQL에서 INNER JOIN으로 참조하는 테이블 중, 삭제/비활성 시 레코드가 제거되는 테이블이 있는지 확인
2. xapm_was_info, xapm_server_info 등 메타 테이블이 alive 상태의 Agent만 포함하는지 확인
3. WAS/Agent 삭제 시 동작하는 DB function/trigger가 관련 메타 테이블을 cascade 삭제하는지 확인
4. 버전 업그레이드/마이그레이션 시 새로 추가된 컬럼(TYPE, STATUS 등)이 INSERT문에 포함되어 있는지 확인
5. UI 조회 API에서 신규 필터 조건(WHERE TYPE = ?)이 추가되었는지, 기존 데이터가 해당 조건을 만족하는지 확인
6. 조회 함수에 중복 호출 방지 플래그(loading guard)가 있는지 확인
7. 비동기 API를 복수 동시 호출하는 경우, 모든 응답 완료 후 플래그를 해제하는지 확인
8. 조회 버튼 UI disable/enable 처리가 있는지 확인
9. 에이전트명에 특수문자(괄호, 공백, 쿼테이션 등)가 포함되어 있는지 확인
10. Application > Local Storage에서 `InterMax_PopUp_Param`의 `wasId` 값 확인
11. 페이지 로딩 후 충분히 대기(10초+)한 뒤 첫 조회 시 에러 재현 여부 확인 (미재현=타이밍 이슈 확정)
12. `Comm.oldServerInfo` 로딩 완료 시점과 `AllWasList` 구성 시점 간 순서 확인
