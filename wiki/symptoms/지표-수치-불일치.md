## 하위 증상 분류
- **CPU 수치 비정상**: 연계 제품 CPU 값이 100배 과대 표시, 송수신 단위 변환 누락 (IMX-9284)
- **동시사용자 집계 오류**: JSPD webId 설정 변경으로 쿠키 기반 집계 미동작 (IMX-9494)
- **지표명 불일치**: .NET 알람 지표명이 JVM 이름으로 표시되는 라벨 불일치 (IMX-7631)
- **시간 조건 역전**: DatePicker에서 매시 정각 전후 From>To 시간 역전 (IMX-9236)

## 공통 패턴

(각 사례가 서로 다른 수치/지표 계층에서 발생하여 단일 패턴으로 일반화하기 어려우나, 공통적으로 "데이터 변환/매핑 계층에서 누락"이 원인. 송신측과 수신측 간 단위/이름/시간 변환이 일관되게 적용되지 않는 패턴.)

## 조사 시 체크포인트
1. CPU 값이 100% 초과인지 확인 — 100배 스케일 전송 후 변환 누락 가능성
2. 동일 API를 다른 연계 제품(MFO, MFS 등)에서 호출할 때 정상인지 비교
3. 송신측에서 100배 곱셈 여부 확인 — 수신측 바이너리 파서에서 /100 변환 여부 확인
4. `jspd.prop.ini`에서 `USE_SESSIONID_FOR_WEBID` 값 확인 (false여야 쿠키 기반 집계)
5. `DISABLE_WEBID` 값 확인 (기본값이 true이므로 반드시 false로 명시 필요)
6. 브라우저 개발자 도구에서 `_xm_webid_1_` 쿠키 생성 여부 확인
7. DB 테이블(XAPM_ALERT_CONFIG)의 ALERT_RESOURCE_NAME 칼럼에 저장된 이름 확인
8. 프론트엔드에서 서버 타입(DOTNET/JVM) 분기 처리 여부 확인
9. jvmStatTransObj 변환 매핑이 해당 화면에 적용되어 있는지 확인
10. DatePicker의 From/To 시간이 역전되어 있는지 (From > To) 확인
11. 매시 정각~정각+N분 사이에만 재현되는지 확인
12. DatePickerForPa.js / DatePicker.js에서 toHour, toMin 변수가 tDate 기준인지 확인
