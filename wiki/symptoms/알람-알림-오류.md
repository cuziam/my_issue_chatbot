## 하위 증상 분류
- **SMS 미발송**: SMS_FLAG 판정 로직 결함 또는 sms_server_list 매핑 누락 (IMX-8895, IMX-9643)
- **알람 연계 실패**: 대시보드 알람 자동 연계 미동작, 서비스명 설정 오류 (IMX-8931)
- **알람 소리 오작동**: 의도하지 않은 알람 레벨이 소리 필터를 통과하여 재생 (IMX-9515)
- **알람 타입 오설정**: alert_type 하드코딩으로 알람 유형 구분 불가 (IMX-9510)
- **알람 파라미터 누락**: SMS adaptor 연계 시 생성자 분기에서 필드(guid 등) 누락 (IMX-9582)
- **DB 알람 정보 부족**: 알람 색상 기준 불명확, 상세 정보 확인 불가 (IMX-8945)

## 공통 패턴

- **SMS 발송 경로 데이터 누락**: SMS 미발송의 근본 원인은 SMS 발송 판정/수신자 조회 시 필요한 데이터가 DB에 누락되는 것. 알람 자체는 정상 동작하나 SMS 연동 경로에서 DB 레코드 누락이 원인.
- **알람 유형별 분기 불완전**: 새 알람 유형(TP Stat Alert 등) 추가 시 기존 하드코딩된 타입 판별/생성자 호출 분기에서 누락되는 패턴.

## 조사 시 체크포인트
1. XAPM_ALERT_HISTORY 테이블에서 SMS_FLAG 값 확인 (0이면 미발송)
2. XAPM_ALERT_CONFIG에 서버 알람 레코드 존재 여부 확인
3. sms_server_list 테이블에서 해당 server_id의 매핑 존재 여부 확인
4. autowasid 사용 환경인 경우 WAS 추가 후 SMS 매핑이 자동 등록되었는지 확인
5. CommDash.js의 `Dash.Comm.svcName`과 `Dash.Comm.svcId` 값이 고객사 환경에 맞게 설정되어 있는지 확인
6. 알람 소리 설정 확인: 내 설정 > 알람 설정에서 어떤 레벨이 체크되어 있는지
7. WebSocket 패킷에서 전달되는 alert_level 확인 (Warning=1, Critical=2)
8. 수집서버 재시작/모듈 기동 시 자동 생성되는 시스템 알람의 alert level 확인
9. AlertConfig.fromCDO() 메서드에서 alert_type이 CDO에서 동적으로 읽어오는지 확인
10. SMS adaptor 로그에서 `info.guid` 값이 NULL인지 확인
11. TcpReadAlarmHistory.java에서 Alert 유형별 SMSData 생성자 호출 분기 확인
12. MFO 연계가 설정되어 있는지 확인 (`useExtMaxGaugeDetail` 활성화 여부)
13. `/api/v1/intermax/rtm/linkAlarm` API 응답에서 alertLevel 값 확인
