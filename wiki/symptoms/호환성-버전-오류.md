## 하위 증상 분류
- **패치 호환성 오류**: 커스텀 ext와 표준 패치 간 버전 불일치로 서비스 장애 (IMX-9512)
- **클래스 버전 호환성 오류**: JDK 버전 불일치로 클래스 로딩 실패 (IMX-9689)
- **모듈 버전 불일치**: nginx 동적 모듈 patch 버전 불일치로 기동 실패 (IMX-9383)
- **인코딩 깨짐**: FileReader charset 미지정으로 UTF-8 파일의 한글이 깨지는 현상 (IMX-9551)

## 공통 패턴

(2건 이상 동일 패턴이 쌓이면 상세 작성 예정. 현재 각 사례의 호환성 문제가 서로 다른 계층에서 발생: Java ext API 호환성, JDK class file version, nginx 모듈 바이너리 버전, 파일 인코딩.)

## 조사 시 체크포인트
1. 패치 적용 전후 어떤 컴포넌트(JSPD/imxtxn/ext)가 변경되었는지 확인
2. ext와 imxtxn이 동일 베이스 버전으로 빌드되었는지 확인
3. 패치 원복 시 정상 복구되는지 확인 (JSPD 기인 여부 판별)
4. 커스텀 ext 사용 환경인지 확인 (커스텀 ext는 표준 패치와 호환성 문제 가능)
5. 런타임 JDK 버전 확인 (IBM JDK 1.6 등 레거시 환경 여부)
6. `javap -verbose {클래스}.class`로 class file major version 확인 (50=1.6, 51=1.7, 52=1.8)
7. jspd-ext.jar가 별도 배치되어 있는지 확인 (`{JSPD_HOME}/lib/jspd-ext*.jar`)
8. nginx 버전 확인: `nginx -v`로 정확한 major.minor.patch 확인
9. 설치 패키지의 `imx_mod/` 디렉토리에서 해당 nginx 버전과 정확히 일치하는 .so 파일 존재 여부 확인
10. OS의 LANG 환경변수 확인 (`locale | grep LANG`)
11. JVM `file.encoding` 시스템 프로퍼티 확인 (`-Dfile.encoding=UTF-8` 지정 여부)
12. SQL 파일/properties 파일을 읽는 코드에서 `FileReader` 사용 시 charset 명시 여부 확인
