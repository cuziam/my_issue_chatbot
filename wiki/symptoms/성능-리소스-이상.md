## 하위 증상 분류
- **DB CPU 과부하**: PostgreSQL 자정 배치 작업으로 CPU 급등 (IMX-8972)
- **에이전트 CPU 과부하**: .NET Agent CLR Profiler로 대상 프로세스 CPU 200% 상승 (IMX-9606)
- **메모리 누수/OOM**: HotDeploy 환경에서 캐시 Map에 객체 무한 누적 (IMX-9480)
- **로그 폭증**: 반복 에러로 로그 용량 급증, 디스크 풀 위험 (IMX-8586, IMX-9534)
- **로그 파일 미생성**: logger 레벨 불일치로 로그파일이 자정에 생성되지 않는 현상 (IMX-9333)
- **무한 로딩**: JavaScript TypeError로 초기화 로직 중단, 화면 무한 로딩 (IMX-8586, IMX-9227)

## 공통 패턴

- **반복 에러 → 로그 폭증**: DB 컬럼 크기 부족, SQL 에러, 클래스 로딩 실패가 반복적으로 발생하여 에러 로그가 대량 누적. 에러 자체보다 로그 디스크 용량 소진이 실질적 위협.
- **클라우드 환경 특유의 문제**: AWS RDS, Kubernetes 환경의 긴 엔드포인트/동적 스케일링이 기존 코드의 고정 크기 제약과 충돌.
- **JavaScript TypeError로 화면 장애**: 비동기 초기화 타이밍 또는 신규 기능 추가 시 함수/변수 미정의 상태에서 호출되어 무한 로딩 발생.

## 조사 시 체크포인트
1. `pg_stat_activity`에서 `state='active'`인 장시간 실행 쿼리 확인
2. 게더 로그에서 `[PARTITION]`, `[VACUUM]`, `[ANALYZE_PG_CATALOG]`, `[SUMMARY]` 키워드 확인
3. 게더 설정에서 `analyze_timeout` 값 확인 (기본값 0 = 무제한)
4. 에이전트 적용 전후 대상 프로세스(w3wp.exe 등)의 CPU 사용률 비교
5. profile.conf의 `enable_trycatch`, `enable_static`, `trace_code_depth` 설정 확인
6. 힙 덤프에서 JSPD 관련 객체의 Retained Size 확인
7. ConcurrentHashMap 엔트리 수가 비정상적으로 큰지 확인
8. HotDeploy/클래스로더 교체가 반복되는 환경인지 확인
9. DGM/PJS 로그 디렉토리에서 특정 에러 메시지가 반복 기록되는지 확인
10. 로그 파일 용량 증가 추이가 비정상적인지 확인 (24시간 기준)
11. DGServer.xml의 `<log_level>` 설정값 확인 (info/debug)
12. XmAlarmLogger의 각 메서드가 실제로 동일 레벨의 logback 메서드를 호출하는지 확인
13. 브라우저 개발자 도구(F12) Console에서 TypeError 또는 undefined 관련 에러가 반복 발생하는지 확인
14. Kubernetes/Tanzu 등 Scale in/out 환경에서 자동 스케일 관련 로직이 비동기 초기화와 경합하는지 확인
