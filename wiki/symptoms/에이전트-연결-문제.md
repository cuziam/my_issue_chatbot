## 하위 증상 분류
- **Alive/Down 표시 오류**: 정상 복귀 후에도 DOWN 상태가 유지되는 현상 (IMX-9399, IMX-9577)
- **에이전트 목록 불일치**: RTM과 PA 에이전트 목록 차이, 삭제 Agent 잔존 (IMX-9668)
- **Autowasid 발급 실패**: autowasid 모드 불일치로 wasid=0 발급, 유령 에이전트 생성 (IMX-9508)
- **공유 메모리 오류**: APIM 에이전트 공유 메모리 미생성/구조체 손상 (IMX-9564, IMX-9577)
- **EtoE 프레임 오류**: txnName null 시 TypeError로 EtoE 모니터링 불가 (IMX-9388)
- **MFO 세션 목록 미표시**: MFO 연동 DB 모니터 차트 정상이나 세션 그리드 빈 상태 (IMX-9518)

## 공통 패턴

- **DataGather 상태 갱신 미도착**: DataGather로의 상태 갱신 데이터가 미도착하면 UI에 DOWN 상태가 유지됨. 원인은 다르지만 (정상 복귀 패킷 미전송 vs 공유 메모리 읽기 실패), DataGather가 갱신 신호를 받지 못하면 반영되지 않는 구조가 핵심.
- **APIM 공유 메모리 문제**: C 네이티브 데몬과 Java DataGather 간 구조체 크기 일치가 필수적. 기동 순서 미준수나 버퍼 오버플로우로 공유 메모리 손상 발생.

## 조사 시 체크포인트
1. DGServer 로그에서 해당 서버의 "Active Down" 알람 이력 확인
2. 정상 복귀 후 active_count/down_count 갱신 패킷이 전송되었는지 확인
3. 브라우저 새로고침(F5)으로 해결되는지 확인
4. Option.conf에 isUseAliveDownInfo 옵션 존재 여부 확인 (v5.3 이상에서만 지원)
5. RTM과 PA 에이전트 목록 소스 차이 확인: RTM=실시간, PA=실시간+이력 포함
6. `wasDBComboBoxForPa`의 `isAddOldServer` 옵션이 true인지 확인
7. `jspd.prop.ini`의 `TYPE_AUTOMATIC_WASID` 값 확인 (1~4)
8. DGServer.xml의 `auto_scale_was_id_mode` 설정이 `true`인지 확인
9. DG 로그에서 `[AUTO ASSIGN WAS ID]` 메시지 확인
10. `imxapimadmin -c`로 공유 메모리가 생성되었는지 확인 (`ipcs -m`)
11. 기동 순서 확인: `imxapimadmin -c` → `imxosm -D` → `imxtxn -D` → 업무 프로세스
12. 커널 파라미터(`shmmax`, `shmall`) 값이 필요 메모리 크기보다 큰지 확인
13. 브라우저 개발자 도구(F12) Console에서 `TypeError: Cannot read property 'trim' of undefined` 확인
14. MFO 연동 DB 모니터 타이틀에 `[MFO:...]` 형태로 MFO 이름이 표시되는지 확인
15. JSPD Agent가 DB 세션과 연결되어 client_identifier(`_xm` prefix)를 설정하고 있는지 확인
