# Wiki Schema

wiki-writer agent가 위키 페이지를 작성/갱신할 때 따라야 하는 규칙입니다.

## 일반 원칙

1. **report.md에 명시된 내용만 기록** — 추론이나 추측은 넣지 않는다
2. **기존 내용을 삭제하지 않는다** — append 또는 테이블 행 추가만 한다
3. **교차 참조**: 관련 페이지가 있으면 `[페이지명](../category/slug.md)` 형식으로 링크한다
4. **파일 네이밍**:
   - `symptoms/`: **9개 상위 카테고리 고정**. 새 페이지를 만들지 않고 기존 카테고리에 사례를 추가한다.
   - `components/`: 제품/기술 고유명은 영문 유지 (예: `platformjs.md`, `datagather.md`)
   - `customers/`: 한글 고객사명 사용 (예: `현대차증권.md`, `아모레퍼시픽.md`). 공백 대신 하이픈 사용.
5. **고객사명**: task.json의 `custom_fields`에서 추출하거나, 태스크 제목에서 추출한다

## 증상 카테고리 (9개 고정)

새 이슈를 다음 카테고리 중 하나에 분류한다. **새 카테고리를 만들지 않는다.**

| 카테고리 | 파일명 | 해당 증상 예시 |
|---------|--------|-------------|
| UI 렌더링 오류 | `UI-렌더링-오류.md` | 텍스트 겹침, 노드 겹침, 화면 미표출, 위젯 오류, 차트 표시 오류 |
| 데이터 조회 이상 | `데이터-조회-이상.md` | 데이터 미조회, 조회 중복, 조회 조건 불일치, 첫 조회 실패 |
| 데이터 수집 오류 | `데이터-수집-오류.md` | SQL 미수집, E2E 유실, 패킷 미전송, 데이터 중복 삽입 |
| 설정 적용 실패 | `설정-적용-실패.md` | 설정 CRUD 오동작, 설정 미적용, 신규 타입 미반영, 연계 타입 불일치 |
| 알람/알림 오류 | `알람-알림-오류.md` | SMS 미발송, 알람 연계 실패, 알람 소리 오작동, 파라미터 누락 |
| 성능/리소스 이상 | `성능-리소스-이상.md` | CPU 과부하, 메모리 누수, 로그 폭증, 무한 로딩 |
| 에이전트 연결 문제 | `에이전트-연결-문제.md` | Alive/Down 오류, 에이전트 목록 불일치, 공유 메모리 오류 |
| 호환성/버전 오류 | `호환성-버전-오류.md` | 패치 호환성, 클래스 버전, 모듈 버전, 인코딩 깨짐 |
| 지표/수치 불일치 | `지표-수치-불일치.md` | CPU 수치 비정상, 동시사용자 집계 오류, 지표명 불일치 |

## 페이지 포맷

### symptoms/{카테고리}.md

~~~
# {카테고리명}

## 관련 키워드
{검색/매칭용 키워드. 쉼표 구분}

## 과거 사례
| 이슈 | 고객사 | 컴포넌트 | 버전 | 근본 원인 요약 | 해결 방법 | 핵심 파일 |
|------|--------|----------|------|--------------|----------|----------|
| IMX-XXXX | {고객사} | {컴포넌트} | {버전} | {1줄 원인} | {패치/설정변경/버전업/자연해소/-} | {파일:라인} |

## 하위 증상 분류
{어떤 세부 증상이 이 카테고리에 속하는지 간략히 설명}

## 공통 패턴
{2건 이상 사례가 쌓이면 작성. 반복되는 원인/해결 방향}

## 조사 시 체크포인트
{이 증상이 나오면 확인해야 할 항목. 번호 목록}
~~~

~~~

## 갱신 규칙

### 증상 페이지에 사례 추가 시
1. 이슈의 증상을 9개 카테고리 중 하나에 분류한다
2. 해당 카테고리 페이지를 Read한다
3. "과거 사례" 테이블에 새 행을 추가한다 (동일 IMX-XXXX가 있으면 추가하지 않는다)
4. "관련 키워드"에 새 키워드가 있으면 추가한다

### 컴포넌트/고객사 페이지 갱신 시
1. 해당 페이지를 Read한다
2. 테이블에 새 행을 추가한다 (동일 IMX-XXXX가 있으면 추가하지 않는다)
3. 컴포넌트 페이지의 "자주 관련되는 증상"에 새 카테고리 링크가 필요하면 추가한다

### 새 컴포넌트/고객사 페이지 생성 시
1. 기존 페이지에 해당하는 것이 없을 때만 생성한다
2. 페이지 생성 후 반드시 index.md에 항목을 추가한다

### index.md 갱신
새 컴포넌트/고객사 페이지를 생성하면 해당 카테고리 아래에 한 줄 추가한다.
(symptoms는 9개 고정이므로 추가하지 않는다)

### log.md 갱신
모든 갱신 작업 후 log.md 맨 아래에 한 줄 추가한다:
```
- {날짜} | {task_id} | {갱신된 페이지 목록} | {신규/추가}
```
